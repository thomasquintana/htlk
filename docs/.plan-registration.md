# Executable registration and codec integration plan

Status: CBOR, digests, the executable envelope, lexical identifiers, and canonical
type/port records are implemented under the Draft 0.1 contract. Runtime
registration and graph-level semantic verification remain unimplemented.
This is a greenfield project: no compatibility aliases or fallback formats exist.

Authority: `specs/compiler-spec.md`, `specs/htlk-executable.cddl`,
`specs/runtime-spec.md`, and the unified baseline in `specs/README.md`.

## Completed executable envelope API

The crate exposes `ExecutableEnvelope`, `EnvelopeError`, and supported format/version
constants under the contract above. Payload bytes are opaque at this outer layer;
inner CanonicalDocument validation remains registration work.

- [x] Agree and document the exact envelope fields and fingerprint preimage.
- [x] Document the contract with exact-byte vectors and deterministic diagnostic
  precedence for records with multiple schema failures.
- [x] Add `ExecutableEnvelope` with private fields and read-only accessors, plus
  `EnvelopeError` for codec, schema, format/version, and fingerprint failures.
- [x] Add construction, canonical encoding, and strict decoding using existing
  `htlk_cbor::Limits`. Do not add a `RegistrationLimits` type in this increment.
- [x] Keep format and version checks explicit. Preserve the exact payload bytes
  and verify their prescribed fingerprint before returning a checked envelope.
- [x] Test canonical bytes, round trips, schema errors, unsupported format/version,
  malformed/mismatched fingerprints, tampered payloads, codec limits, and trailing
  bytes. A valid envelope does not imply a structurally valid executable graph.
- [x] Pass ten envelope tests and remove the completed envelope plans. Remaining
  audit documentation and CI tasks have been transferred to the checklist above.

## Next increments: execution options and remaining payload records

The payload schema and identity formulas are now available; do not invent another
wire format or block on a missing companion document. Follow compiler sections
4-7 and `specs/htlk-executable.cddl`, in small implementation slices:

- [ ] Use the completed `Identifier`, `ValueType`, and `Port` in containing graph
  records. Validate identifier-keyed port tables separately from arbitrary
  string-keyed record fields; apply reserved-root restrictions in their contexts.
- [ ] Add execution-limit and retry records, distinct from codec Limits; then
  canonical expressions, paths, functions, and prompt templates. Contract fields
  are `preconditions` and `postconditions`; omitted contracts normalize to true.
- [ ] Add scope/node/edge/operation records, including carried and next boundaries,
  deterministic ordering, local IDs, and contextual scope/loop rules.
- [ ] Add profile/engine/library/server/MCP binding records and referenced policy
  and schema documents, using actual external protocol/implementation versions.
- [ ] Assemble `CanonicalDocument` with exact fields `ir_version`, `graph_id`,
  `profile`, `root_scope`, `scopes`, `templates`, `bindings`, `libraries`,
  `schema_uris`, and `documents`.
- [ ] Add bounded record hashing with a closed kind set (scope, node, template,
  binding, server), using raw UTF-8 `htlk.<kind>/0.1\n` plus canonical record bytes.
- [ ] Implement JCS/JSON numeric rules and offline schema/document resolution;
  external JSON digests hash JCS bytes without an HTLK prefix.
- [ ] Keep raw-envelope parsing distinct from full executable validation. Reject
  empty/malformed/noncanonical or wrong-schema payloads before a graph is accepted.
