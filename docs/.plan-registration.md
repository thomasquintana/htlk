# Executable registration and codec integration plan

Status: pending. Standalone `htlk-cbor` implementation and conformance checks
are complete. Compiler and runtime depend on it; domain call sites remain to
be implemented with their executable schemas.

This temporary plan carries forward unfinished consumer work from the completed
CBOR plan. Update it as registration is designed and implemented; remove it
when the tasks below are complete. It is not a claim that registration exists.

## Inputs and decisions needed

- [ ] Reconcile the Draft 0.3 runtime registration requirements with the compiler
  companion specification, including exact envelope/payload schemas, format
  version, fingerprint preimages, and reachable-record closure.
- [ ] Define per-document limits and aggregate registration allowances. Keep
  limits as configuration and accounting as per-request mutable usage.
- [ ] Specify which counters span envelope and payload decoding: at minimum
  total visited values and copied text/byte payloads. Decide whether encoded
  input processing needs its own shared work counter.
- [ ] Keep document nesting checks explicit for each decode. Define total
  retained-memory accounting while the outer payload and decoded inner value
  coexist; do not treat payload-byte counters as exact heap measurements.
- [ ] Document deliberate charges for the outer payload byte string and its
  subsequently decoded values. A second decode must not reset the request's
  aggregate allowance, and error paths must not permit a request to regain work
  already consumed.

## Codec interface integration

- [ ] Choose the smallest interface that enforces the agreed aggregate policy:
  a bounded registration-specific composition API or an explicit accounting
  session, based on real call-site needs. Do not expose raw Encoder/Decoder state
  merely to share counters. Keep public one-shot `encode`/`decode` convenient.
- [ ] Preserve strict canonical ingress, per-document checks, checked arithmetic,
  fallible allocation, and decoder error offsets when sharing accounting.
- [ ] Define ownership of counters, reset rules, and failure behavior. Separate
  concurrent requests must never share mutable usage accidentally.
- [ ] Add compiler executable-production calls to the shared encoder when the
  executable schema exists. Test exact bytes and fingerprint preimages.
- [ ] Add runtime envelope and nested-payload decoding calls. A decoded outer
  byte string is not evidence that its contents are canonical.

## Registration validation and persistence

- [ ] Validate exactly the declared envelope fields, requiredness, version, and
  domain-separated fingerprint over the exact payload bytes.
- [ ] Independently decode and validate payload record schemas, references,
  content-addressed record digests, external JSON digests, and reachable closure.
- [ ] Connect the shared graph verifier and exact implementation-profile checks.
- [ ] Apply deployment attestation policy separately from structural validity.
- [ ] Map codec diagnostics into contextual runtime failures; preserve protected
  diagnostics without exposing untrusted value contents in public errors.
- [ ] Commit only fully verified immutable registrations, with same-envelope
  idempotency and same-fingerprint/different-bytes integrity failure behavior.

## Required integration checks

- [ ] Each document individually fits its limits but combined usage exceeds the
  request allowance: reject before additional allocation or authoritative commit.
- [ ] Exact aggregate boundary succeeds; one unit over fails for each shared
  counter, including map keys and nested payload data.
- [ ] Malformed or noncanonical inner CBOR inside a canonical envelope fails.
- [ ] Invalid fields, profile, digests, closure, or required attestations leave
  no authoritative registration behind.
- [ ] Failed decode/validation and duplicate requests obey documented accounting
  and idempotency rules; concurrent requests have independent accounting.
- [ ] Encoding the same normalized executable yields identical bytes, and the
  runtime accepts those bytes only after all structural checks pass.
- [ ] Run focused tests, workspace formatting/Clippy/tests/rustdoc/package checks,
  and update permanent documentation before deleting this plan.
